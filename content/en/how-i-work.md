## HOW I WORK

Most of my days go into research, analysis and documentation that support decisions, more than into writing code myself. A lot of it is review and technical direction, moving between the business view and engineering detail, and AI is part of almost every step.

A good part of my research is about routing. No single model is the best choice for every step of a task, so I route requests by profile and by task phase and weigh quality against cost for each model.

I also study how agents work as a team. A task is split into specialized roles, each with a narrow scope, so planning, implementation, testing and review happen as separate steps that check each other.

The other half is memory and retrieval. Agents need a shared memory they can both read from and write to: a global layer plus one per project, kept as readable text alongside a knowledge graph, so what an agent knows can be checked and corrected.

I also measure whatever I can: which model answered each call, how many tokens it used and what it cost, so choices about models and workflows rest on numbers.
